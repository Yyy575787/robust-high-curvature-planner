# robust-high-curvature-planner
**Robust Local Trajectory Planning for High-Curvature Narrow Roads with Static Obstacles**

项目名称：`robust-high-curvature-planner`

本项目研究高曲率 U 型弯、窄道路与静态障碍物共同作用下的局部轨迹规划问题，计划以 CommonRoad Reactive Planner 为主要实验基线，验证曲率感知参考线处理、多走廊候选轨迹和可行性回退机制的作用，并在后期将研究结论映射到 Apollo 中的相关规划问题。

> 当前状态：研究启动与方案定义。基线环境、官方示例和改进方法尚未在本仓库完成验证；下文的效果描述均为待验证假设，不代表已有实验结论。
>
> 计划周期：2026 年 9 月 21 日至 12 月 13 日，共 12 周；默认每周投入约 10～12 小时。

## 1. 研究背景

在高曲率窄道路中，车辆可使用的横向空间有限，车身尺寸、最小转弯半径、道路边界与障碍物位置会共同限制可行轨迹。即使道路中心线连续，沿参考线生成的候选轨迹仍可能因为运动学限制、车身扫掠区域碰撞或越界而被淘汰。

本项目关注的实际现象包括：U 型弯中可行空间被过度收缩、绕行方向选择不稳定、局部规划持续失败，以及车辆在弯道后半段反复停车。Apollo 阶段还将检查路径边界压空与 Piecewise Jerk 优化无解等具体问题。

研究将从可复现的采样式规划基线出发，先建立失败证据，再逐步引入方法改进，考察规划成功率、安全间距、轨迹质量与计算开销之间的关系。

### 研究范围

- 高曲率 U 型弯与窄道路。
- 静态障碍物及不同的障碍物位置、偏移和尺寸。
- 初始横向误差、初始航向误差，以及定位、障碍物信息和参考线的扰动。
- 暂不考虑动态对向车辆，不引入深度学习。
- 有限借道仅在场景明确允许的可行驶区域内进行；不将其视为真实道路通行规则验证。

## 2. 核心问题

| 核心问题 | 需要回答的具体问题 | 计划观察的证据 |
| --- | --- | --- |
| 高曲率区域的参考线与坐标转换 | 参考线局部几何、噪声和 Frenet 坐标转换是否影响候选轨迹的可执行性？ | 参考线曲率、坐标转换误差、运动学淘汰原因 |
| 狭窄空间中的搜索覆盖 | 现有采样是否遗漏可通行的左侧或右侧绕行轨迹？ | 候选覆盖范围、各走廊可行数量、碰撞与越界检查结果 |
| 所有候选失败后的处理 | 能否通过降速和扩大搜索恢复可行解，并在无法继续时安全停车？ | 回退触发原因、各级回退成功率、停车次数 |
| 安全与效率的共同保证 | 提高完成率是否伴随间距下降、轨迹不平顺或计算开销过大？ | 安全间距、曲率、加速度、jerk、平均与 P95 耗时 |
| 结论在不同规划器中的适用性 | CommonRoad 中发现的失败机理能否解释并改善 Apollo 中的对应现象？ | 分别记录的 CommonRoad 与 Apollo 对比案例 |

**失败类型需要分开统计：** CommonRoad Reactive Planner 主要检查“是否存在通过约束检查的候选轨迹”；Apollo 中的“路径边界压空”与“优化器无解”属于其对应模块的失败事件，不能直接合并为同一种无解率。

已知几何不可通行的场景应单独标注，用于评估安全停车能力。对于尚不明确是否可通行的场景，应记录证据，避免仅凭规划失败就判断道路不可通行。

## 3. 研究假设与方法路线

**核心假设：曲率感知参考线处理 + 多走廊候选轨迹 + 可行性回退机制，可以减少路径边界压空、规划失败和反复停车，同时保持安全间距与计算效率。**

该假设需要在各自系统中通过实验验证；CommonRoad 的完成率提升不能直接证明 Apollo 的优化无解问题已经解决。

| 假设 | 计划实现 | 验证方式 |
| --- | --- | --- |
| H1：曲率感知处理能够减少高曲率区域的候选失效 | 检查参考线几何与坐标转换误差，根据曲率调整采样范围、采样密度和规划长度 | 比较原始基线与“基线 + 曲率感知”的完成率、无解率和约束淘汰分布 |
| H2：多走廊候选能够提高窄路障碍物绕行的搜索覆盖 | 生成保持自车道、左偏移、右偏移和必要时有限借道的候选 | 比较原始基线与“基线 + 多走廊”的可行候选数量、完成率和轨迹左右切换情况 |
| H3：分级回退能够降低持续失败和反复停车 | 正常规划失败后依次尝试降速扩大搜索、放宽非安全相关约束和安全停车 | 比较原始基线与“基线 + 回退”的失败持续时间、恢复成功率和停车次数 |
| H4：三个模块组合后能取得综合收益 | 在统一的安全与可执行性筛选后比较舒适性和效率 | 对比完整方法与各消融组，并报告安全性、轨迹质量和计算开销 |

计划采用以下处理顺序：

```text
场景、车辆状态与参考路径
          ↓
曲率感知参考线处理与自适应采样
          ↓
多走廊候选轨迹生成
          ↓
安全与可执行性筛选
          ↓
在可行轨迹中比较舒适性和效率
          ↓
输出轨迹；无可行轨迹时进入分级回退
```

分级回退顺序：

```text
正常轨迹 → 降速并扩大搜索 → 放宽非安全相关约束 → 安全停车
```

碰撞、允许行驶区域边界、车辆物理可执行性和预先设定的安全间距要求不因回退而放宽。停车轨迹也需要经过安全检查；若当前状态已经无法保证安全停车，应明确记录该失败，不能将“发出停车指令”等同于“安全停车成功”。

## 4. 计划使用的基线与实验设置

### 4.1 主要基线：CommonRoad Reactive Planner

采用 [CommonRoad Reactive Planner 官方仓库](https://github.com/CommonRoad/commonroad-reactive-planner)作为主要基线。该规划器在 Frenet 坐标系中采样多项式轨迹，并依据代价选择轨迹；官方提供 `run_planner.py` 示例入口。

基线复现阶段计划完成：

1. 固定上游版本或 commit SHA，记录依赖、运行平台与硬件。
2. 按选定版本的官方依赖建立独立 Conda 环境。
3. 跑通官方示例，保存实际命令、配置、终端日志和轨迹图或视频。
4. 梳理参考路径输入、Frenet 采样、横纵向组合、运动学检查、碰撞检查、代价计算、轨迹选择及失败处理链路。
5. 保留原始基线行为；为适配场景所做的配置调整、兼容性修复和日志改动均单独记录。

安装命令、Python 版本和运行说明将在实际验证后补充。当前 README 不构成已验证的安装教程。

### 4.2 对照与消融组

| 编号 | 实验组 | 用途 |
| --- | --- | --- |
| B0 | 原始基线 | 建立失败分布与性能参考 |
| B1 | 基线 + 曲率感知 | 验证 H1 |
| B2 | 基线 + 多走廊 | 验证 H2 |
| B3 | 基线 + 回退机制 | 验证 H3 |
| B4 | 完整方法 | 验证综合收益与开销 |

所有实验组使用相同的场景、车辆参数、初始条件、安全阈值和任务终止条件。对存在随机性的实验固定并记录种子；使用相同硬件和计时范围比较耗时，同时记录各方法的候选数量与搜索预算。

### 4.3 场景集

最低建立 **30 个基础场景**，再从中选取场景增加定位、障碍物信息和参考线扰动。场景参数包括：

- 转弯半径与道路宽度。
- 障碍物纵向位置、横向偏移和尺寸。
- 车辆初始横向误差与初始航向误差。
- 参考线局部噪声。

扰动实验需要区分真实场景与规划器接收到的信息：安全性按真实几何和实际执行轨迹评价，扰动分布、幅值和种子均应留档。

### 4.4 Apollo 验证

Apollo 作为后期工程验证平台，具体版本与场景将在第 10 周前确定。重点检查：

- 路径边界是否压空、Piecewise Jerk 是否频繁无解。
- 自车道 nudge 与有限借道是否合理。
- U 型弯后半段是否停车，以及是否出现路径左右跳变。
- 改进前后的规划耗时变化。

Apollo 的模块失败率与 CommonRoad 的候选失败率分别报告。

## 5. 评价指标与日志

### 5.1 评价指标

下表为计划采用的统计口径。具体阈值、车辆尺寸、采样周期、超时条件和停车判定规则应在批量实验前写入配置，并在各对照组之间保持一致。

| 指标 | 计划定义与统计口径 | 单位或报告形式 |
| --- | --- | --- |
| 任务完成率 | 在规定时限内到达目标且全程无碰撞、无越界的运行次数 / 总运行次数 | %；同时给出分子与分母 |
| 碰撞率 | 至少发生一次车身与障碍物碰撞的运行次数 / 总运行次数 | % |
| 越界率 | 至少发生一次车身超出预先允许行驶区域的运行次数 / 总运行次数 | % |
| 规划无解率 | CommonRoad 中未返回可执行轨迹的规划周期数 / 总规划周期数 | %；另报回退前的正常搜索失败率 |
| 最小横向间距 | 在约定的局部道路坐标中计算车身轮廓与相关障碍物或道路边界的横向净距，并取运行过程最小值 | m；记录计算方式与适用区域 |
| 最小几何净距 | 在世界坐标中计算车身轮廓到障碍物、允许行驶区域边界的最短距离，分别统计 | m；与碰撞、越界事件共同报告 |
| 最大曲率 | 执行轨迹上的最大绝对曲率 | 1/m |
| 最大横向加速度 | 执行轨迹上的最大绝对横向加速度，注明计算或估计方式 | m/s² |
| jerk | 执行轨迹纵向与横向加速度的时间变化率，分别统计 RMS 和最大绝对值 | m/s³ |
| 规划耗时 | 每个规划周期从规划输入就绪到输出轨迹或失败状态的耗时，包含候选生成、筛选、选择和实际触发的回退 | ms；平均值与 P95 |
| 反复重规划或停车次数 | 单独统计异常连续失败与非目标停车事件；正常周期重规划不计作异常 | 次/运行；记录速度阈值和持续时间 |

高曲率区域的横向投影距离可能不足以描述车身角点间隙，因此同时报告世界坐标下的几何净距。碰撞与越界率分别统计，不要求各类失败比例相加等于 100%。

耗时统计应说明是否包含初始化，并保持相同的可视化和日志设置。成功与失败运行均纳入结果；对于成功后才能完整计算的指标，需要注明样本筛选条件和有效样本数，避免只报告成功样本。

### 5.2 第 2 周前补齐的日志

- 每个规划周期的候选总数，以及通过运动学检查和碰撞检查的数量。
- 各筛选阶段的淘汰原因；明确计数发生在排序、提前退出之前还是之后。
- 最优轨迹各项代价、权重与总代价。
- 单周期规划耗时及主要阶段耗时。
- 无有效轨迹的具体原因、连续失败周期数。
- 回退级别、触发原因及恢复结果；多走廊实现后增加走廊标识与分组统计。

每次实验至少关联：实验编号、场景编号、代码版本、环境信息、配置、实际命令、随机种子（如适用）、指标、日志和可视化文件。

1. 本周完成了什么？
